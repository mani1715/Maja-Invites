# Pixora site-wide refinement

## Direction
The homepage establishes a photographic lavender world. Marketing uses the same artwork with restrained type and generous space. Authentication uses a focused split layout. Community preserves image compositions. Studio and admin screens use quiet surfaces, readable controls, a searchable navigation system and clear recovery states. Customer-owned invitations and published portfolios retain their selected designs.

## Execution
1. Inventory actual routes and shared shells; preserve existing working-tree changes.
2. Fix duplicated routing, navigation omissions, inaccessible mobile navigation, unsupported copy and unresolved-session handling.
3. Apply scoped visual tokens and family-specific typography, media, panels and spacing.
4. Exercise all routable page components at desktop/mobile sizes against intentionally unavailable services. Capture review screenshots and distinguish these from populated account testing.
5. Test navigation, session recovery and route access with isolated fixtures; run production build and homepage regression.

## Preserved contracts
No deployment; no price or entitlement changes; no database migrations; no customer content changes. Public URLs and legacy redirects remain. PostgreSQL architecture and explicit portfolio publication remain unchanged.

## Review limits
A route screenshot is not a complete functional test. Payment, real identity, media upload, email delivery, role-specific data, camera permissions and populated production records require service-backed staging acceptance. Browser runs use local fixtures and cannot prove a defect-free production system.
